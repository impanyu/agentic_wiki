# Shared page resources

Every page includes an `@` picker in chat and **Browse & copy files** in Page files. Browse connected Google Drive, ADMA (including public third-party roots), Dropbox and OneDrive, select files/folders, mention enabled connector or workspace tools, and identify visible page elements. File search filters the current loaded folder; Load more follows provider pagination. References carry exact IDs and are passed as untrusted, permission-checked context to both wiki and application chat. Other enabled API/MCP connectors remain available through the Tools tab and the agent's connector loop; arbitrary MCP services do not automatically get a binary file adapter.

`browse_resources` and `copy_resources` are shared agent tools. Generated apps can use `resources.browse` and `resources.copy`; copying requires explicit submitted task input. Pages remain general workspaces, independent of their main app's connector. The generator is instructed to consider relevant enabled connectors for wiki evidence and to provide reusable inputs, useful controls and supported exports for apps.

Transfers preserve bytes and folder structure and never delete sources. Google Docs/Sheets/Slides export to DOCX/XLSX/PPTX. Google creates a new file; Dropbox and OneDrive reject name conflicts; ADMA auto-renames conflicts according to its API. ADMA creates private files and can reject unsupported formats. Page files create a new attachment. Folder separators/control characters are mapped to underscores on copies and folder names are limited to 100 characters. Limits: 10 MiB/file, 100 MiB/operation, 200 entries, 12 folder levels. Copies report individual successes/failures; folders over the entry limit fail before writing. A copy ID prevents repeated execution, and an interrupted/uncertain copy must be inspected before a new operation is started. No background job or automatic retry is implied.

Permissions are rechecked for each external operation. Storage uses checked list/read/upload/mkdir tools. ADMA requires checked list_files/list_folders plus download_file/upload_file/create_folder as needed. Existing connector settings are not silently widened: enable the new ADMA download_file and upload_file tools in Connectors. Remote tokens remain server-side. Read-only pages allow personal Page files attachments, but external writes require page write access. Public third-party ADMA folders are sources, not writable destinations.

Validation: mocked binary transports for all four providers, permission and idempotency tests, and HTTP smoke tests covering actual Page files copy, byte equality, deduplication, and unauthorized access. Live external write tests require specific source/destination selection; connection presence alone is not a test authorization.
